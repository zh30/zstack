## 1. Smoke protocol / hypothesis

**Hypothesis:** If we offer **one-click restore of client-specific tab workspaces** to **hands-on support agents at small US SaaS teams** via a single **Join the early-access waitlist** CTA with a truthful planned price **from $9/month**, then **cold / controlled traffic** will produce **≥ ~3–5% visitor → confirmed waitlist CVR** (source-specific; see matrix) and **warm outreach** will produce **≥ ~12–15% CVR plus ≥ 3 qualified replies**, within **10 days**, under the traffic plan below—**without pooling warm and cold rates**.

**Primary metric:** Confirmed waitlist conversions ÷ qualified unique visitors, **by traffic class** (Buttondown confirmed subscriber with stored traffic class as numerator; Plausible unique visitors with matching UTM class as denominator).

**Secondary metrics:** CTA click rate; welcome open rate (diagnostic only); reply rate / “I’d pay” language; cost per confirmed email on ads; form attempts that do **not** become confirmed subscribers.

**Sample plan (do not pool):**

| Traffic class | Min qualified uniques before hard decide | Min confirmed conversions preferred | Notes |
|---------------|------------------------------------------|-------------------------------------|--------|
| **Cold ads** | 150 | 5+ | Meta/Google/Reddit ads; $150 cap |
| **Cold community** | 80 | 3+ | Reddit / forums with founder disclosure |
| **Warm outreach** | 30 | 5+ | Personal DMs/email only; **separate sheet** |
| **Own / social organic** | 40 | 2+ | X posts; not mixed into cold ads CVR |

If a class never hits min visits, mark that class **underpowered**—do not invent a pooled “overall CVR” for kill/continue.

## 2. Metrics, source-specific thresholds, decision rules

### Definitions

| Metric | Definition | Source of truth |
|--------|------------|-----------------|
| Unique visitors | Plausible unique pageviews on landing URL | Plausible |
| CTA clicks | Clicks on primary CTA (nav, hero, final) | Plausible custom event `click_cta` |
| Attempt waitlist | Form submit fired client-side | Plausible `attempt_waitlist` only |
| **Confirmed waitlist** | Email accepted by Buttondown (subscriber record) | **Buttondown export / API** |
| Visitor → email CVR | Confirmed waitlist ÷ unique visitors **same class** | Join Plausible class + Buttondown metadata |
| Welcome open | Opens on welcome email | Buttondown (diagnostic) |
| Intent signals | Replies with real workflow / “I’d pay” / company context | Inbox + notes |
| Revenue | Not tested (no charge in smoke) | N/A |

**Integrity rules:**

- Count conversion **only** after Buttondown confirms the subscriber.
- Do **not** fire a client-side “success conversion” from the raw submit handler.
- Success UI: neutral acknowledgement only unless you use a verified redirect/callback.
- Store `utm_source`, `utm_medium`, `utm_campaign`, and derived `traffic_class` in Buttondown metadata (or separate forms/tags per class). Verify one real test signup per class before Day 1 traffic.
- **Never** combine warm DM CVR with cold ads/community into one headline rate.

### Source-specific thresholds (directional; pre-registered)

| Class | Success bar (continue / deepen) | Weak / rewrite offer | Kill / park class signal | Sample floor |
|-------|----------------------------------|----------------------|---------------------------|--------------|
| **Cold ads** | CVR ≥ 3% **and** CPE ≤ ~$8–10 **and** ≥ 1 meaningful reply or strong qualifier answers | Visits ≥ 150, CVR 1–3%, or CPE > $12 with thin intent | Visits ≥ 150, CVR &lt; 1.5%, no qualifiers after 2 creatives | Min $ spend split; kill creative in 48h if CTR/CPE trash |
| **Cold community** | CVR ≥ 4% **or** ≥ 5 confirmed + ≥ 2 substantive comments/DMs | Visits ≥ 80, CVR &lt; 2.5%, hostile “vaporware” only | Visits ≥ 80, CVR &lt; 1.5%, ban risk / zero constructive feedback | Disclose founder; follow sub rules |
| **Warm outreach** | CVR ≥ 12% **and** ≥ 3 replies with client-switching pain | 30+ contacts, CVR 5–12%, soft “cool idea” only | 30+ contacts, CVR &lt; 5%, zero pain recognition | **Separate dashboard row forever** |
| **Own / X organic** | CVR ≥ 5% on engaged followers **or** high reply quality | Low engagement; curiosity without signup | N/A alone—insufficient to kill product | Supportive signal only |

### Decision matrix (end of Day 10)

| Pattern | Decision |
|---------|----------|
| **Strong cold** (ads or community hits success) **+** warm engaged | **Proceed** to thin MVP / `z-write-prd`; keep waitlist warm |
| **Warm strong, cold weak** | Demand exists in network; **reshape positioning/channels** or ICP; interview waitlist before build |
| **Cold OK CVR, zero replies** after 1 follow-up email | Soft demand → **customer interviews** before code |
| **Traffic OK, CVR weak** both cold classes after 1 hero rewrite mid-test | **Retest offer** (promise/price framing), not more features |
| **Cannot get traffic** despite honest push | Distribution thesis failed → fix channels / ICP, not product scope |
| **Nothing** after min samples on ≥2 cold classes + warm | **Park or reshape ICP**; do not build the extension |

**Mid-test rewrite window:** Days 4–5 only, one hero/subhead change max if cold CVR &lt; 2% with ≥80 cold visits; keep CTA and price chip fixed.

## 4. Form, events, UTMs, implementation pack

### Stack

| Piece | Choice |
|-------|--------|
| Host | **Cloudflare Pages** static site |
| Form / email | **Buttondown** (subscribe API or embed + tags) |
| Analytics | **Plausible** (privacy-friendly; custom events) |
| Domain | Your domain or `*.pages.dev` for smoke |

### Form fields

| Field | Required | Notes |
|-------|----------|--------|
| `email` | Yes | Primary |
| `role` | Optional | e.g. Support agent / Team lead / Other |
| `biggest_pain` | Optional one-liner | Quality over CVR tradeoff—keep optional |
| `utm_source`, `utm_medium`, `utm_campaign` | Hidden | From query string on load |
| `traffic_class` | Hidden | Derived: `cold_ads` \| `cold_community` \| `warm` \| `organic_social` \| `direct_unknown` |
| Consent | Explicit | “Email me early-access updates. Unsubscribe anytime.” unchecked by default |

**Double vs single opt-in:** Prefer Buttondown’s recommended flow for deliverability (often confirmation email). Treat **confirmed subscriber** as conversion, not the first click.

**Success state copy (unverified client submit):**  
“Submission sent — check your inbox if the provider accepts it.”  

**Success state (only after verified callback/redirect):**  
“You’re on the early-access list — check your inbox to confirm.”  

### Plausible events

| Event | When |
|-------|------|
| `pageview` | Automatic |
| `click_cta` | Any primary CTA click |
| `attempt_waitlist` | Form submit attempt (valid client-side email format) |
| Do **not** emit `submit_waitlist` / conversion from submit handler unless Buttondown confirms via callback/redirect you control |

### UTM scheme

Base: `https://YOUR_DOMAIN/`  

| Channel | Example URL |
|---------|-------------|
| Warm DM | `?utm_source=warm&utm_medium=dm&utm_campaign=smoke10&utm_content=personal` |
| Warm email | `?utm_source=warm&utm_medium=email&utm_campaign=smoke10` |
| X organic | `?utm_source=x&utm_medium=social&utm_campaign=smoke10&utm_content=thread1` |
| Reddit r/… | `?utm_source=reddit&utm_medium=community&utm_campaign=smoke10&utm_content=SUBNAME` |
| Indie Hackers | `?utm_source=indiehackers&utm_medium=community&utm_campaign=smoke10` |
| Ads creative A | `?utm_source=ads&utm_medium=cpc&utm_campaign=smoke10&utm_content=crea_a` |
| Ads creative B | `?utm_source=ads&utm_medium=cpc&utm_campaign=smoke10&utm_content=crea_b` |

**Map to `traffic_class`:**  
`utm_source=warm` → `warm`; `utm_source=ads` → `cold_ads`; `reddit|indiehackers|…` community → `cold_community`; `x` organic → `organic_social`; missing → `direct_unknown` (exclude from cold CVR success decisions).

### Implementation notes (spec only — no files modified this run)

User asked **not to modify files** and web/deploy tools are unavailable; treat this as the build checklist:

1. Single `index.html` (or minimal static folder) on **Cloudflare Pages**.  
2. Plausible snippet + event helpers.  
3. Buttondown subscribe with metadata fields for UTMs + `traffic_class`.  
4. Placeholders: `YOUR_DOMAIN`, Plausible domain ID, Buttondown API/form URL, contact email.  
5. Pre-flight tests: valid signup, invalid email blocked, metadata visible on subscriber, Plausible events fire, **no** fake confirmed-success UI.  
6. Spreadsheet tabs: **Cold ads | Cold community | Warm | Organic** — never one blended CVR for the go/kill call.
