# Mom Test rules — z-customer-discovery

Lightweight operational rules inspired by Rob Fitzpatrick’s *The Mom Test*.
Not a book summary — enforcement checklist for the skill.

## Three rules (founder-facing)

1. **Talk about their life, not your idea.**  
2. **Ask about the past, not the future.**  
3. **Talk less; listen more.**

## Question patterns

| Prefer | Avoid |
|--------|--------|
| “Tell me about the last time …” | “Would you use …?” |
| “How do you handle that today?” | “Do you think this is a good idea?” |
| “What have you already tried?” | “If I built X, would you pay?” |
| “What did that cost you (time/money)?” | “How much would you pay?” (too early / hypothetical) |
| “Why was that annoying enough to act?” | “Doesn’t that suck?” (leading) |
| “Who else is involved when this happens?” | Long pitch mid-interview |

## Soft vs hard data

| Soft (keep, low weight) | Hard (high weight) |
|-------------------------|---------------------|
| Opinions about your idea | Specific incidents with dates-ish |
| Generic praise | Named tools + workflows |
| Future promises | Money/time already spent |
| “Someone should build this” | They built a spreadsheet / hired help |

## Mid-interview recovery lines

If you started pitching:

- “Sorry — ignore my product for a minute. Walk me through last Tuesday.”  
- “Before any solution: what did you do the last time this broke?”  

If they only compliment:

- “Thanks — to keep me honest, when was the last time this actually blocked you?”  

## End-of-interview (optional)

Only after stories are collected:

- 30–60s plain description of the idea  
- “Does this change anything about what you already do?”  
- “Who else should I talk to?” (referral = mild positive signal)  

## Red flags in founder notes

- More product adjectives than user stories  
- Zero named tools or processes  
- All interviewees are friends in the same Slack  
- Every gate marked “support” with no quotes
